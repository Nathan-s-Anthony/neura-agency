# Project Planning Workflow

## Purpose

Convert the validated project brief into an actionable technical
and organizational plan.

## Trigger

A project has completed discovery.

## Primary Agent

Tech Lead Agent

## Process

1. Read the project brief.
2. Review requirements.
3. Identify technical requirements.
4. Identify non-technical requirements.
5. Define architecture.
6. Evaluate technology choices.
7. Identify integrations.
8. Identify risks.
9. Break the project into tasks.
10. Define task dependencies.
11. Define acceptance criteria.
12. Identify required specialist agents.
13. Produce the implementation plan.

## Required Outputs

- Architecture
- Technical decisions
- Requirements
- Task breakdown
- Dependencies
- Acceptance criteria
- Agent assignments
- Risks

## Completion Criteria

Planning is complete when:

- The architecture is sufficiently defined.
- Major requirements have been addressed.
- Development tasks are actionable.
- Dependencies are identified.
- Required specialists have been identified.

## Replanning

Planning must be revisited when:

- Requirements materially change.
- Architecture becomes unsuitable.
- A major technical constraint is discovered.
- Development reveals a significant architectural issue.
