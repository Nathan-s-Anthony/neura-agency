# Quality Assurance Workflow

## Purpose

Verify that implemented work satisfies project requirements and
acceptance criteria.

## Trigger

Development work has been marked ready for QA.

## Primary Agent

QA Agent

## Process

1. Read the original requirement.
2. Read the acceptance criteria.
3. Review the implementation.
4. Execute applicable tests.
5. Test expected behaviour.
6. Test edge cases.
7. Identify defects.
8. Record test results.
9. Approve or reject the work.

## Outcomes

### Passed

The work satisfies the applicable requirements.

QA → Delivery

### Failed

The work does not satisfy one or more requirements.

QA → Development

A defect report must explain:

- What failed
- Expected behaviour
- Actual behaviour
- Relevant task
- Severity
- Reproduction information where applicable
