# Client Intake Workflow

## Purpose

Establish the initial project context when a new client request
enters the agency.

## Trigger

A new client provides an idea, problem, requirement, or request
for a product or service.

## Primary Agent

Client Agent

## Process

1. Create a project identifier.
2. Create the project workspace.
3. Record the original client request.
4. Analyze the initial request.
5. Determine whether sufficient information exists to begin
   discovery.
6. Ask clarifying questions when necessary.
7. Create the initial project brief.
8. Identify potential agency capabilities.
9. Submit the project for planning.

## Required Outputs

The workflow must produce:

- Original request
- Project brief
- Initial requirements
- Open questions
- Assumptions
- Potential capabilities

## Completion Criteria

Intake is complete when the project has enough information to
begin formal planning.

The Client Agent must not invent missing client requirements.

Unknown information should be explicitly recorded.

## Failure Conditions

The workflow must pause when:

- The client has provided insufficient information.
- A critical requirement is ambiguous.
- Conflicting requirements exist.
- A required decision requires human input.
