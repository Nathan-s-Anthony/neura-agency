# Project Policy

## Purpose

Define the minimum structure and standards required for an agency
project.

## Project Creation

Every project must have:

- A unique project identifier.
- An original client request.
- A project brief.
- Project status.
- Project ownership information.
- A defined lifecycle state.

## Project Context

Important project information must be persisted.

This includes:

- Requirements
- Decisions
- Assumptions
- Architecture
- Tasks
- Risks
- QA results
- Delivery status

## Requirements

Requirements must be distinguishable from:

- Assumptions
- Suggestions
- Technical decisions
- Future ideas

## Changes

Material changes to project requirements must be recorded.

A material change may require the project to return to:

Discovery

or

Planning

depending on its impact.

## Project Completion

A project must not be considered complete until required workflow
stages have been satisfied.
